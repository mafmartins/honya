# Honya MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a local Electron app that translates English ASS dialogue into PT-PT or PT-BR and writes a new ASS file.

**Architecture:** Pure TypeScript modules parse ASS, compile a style card, translate in batches of 25, escalate a nested preset, and gate assisted export on flags. Electron is the window, the key store, and the installer. A bundled `ffmpeg` grabs optional frames. Tests call the modules with a fake completer and never open a window.

**Tech Stack:** TypeScript, Vitest, Electron, electron-builder, Electron `safeStorage`, `ass-compiler` (MIT).

## Global Constraints

- Local Electron app on Linux, macOS, and Windows. No account and no hosted service.
- One English ASS file per session. Output variant is `pt-pt` or `pt-br`.
- Dialogue events only. Signs, songs, and karaoke are copied through unchanged.
- Read ASS with `ass-compiler`'s `parse`. Do not use `compile`, `decompile`, or `stringify` to write the file. Those rewrite tags and reorder events.
- TypeScript is strict: `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes`. No `any`, no `as any`, no `as unknown as`, no `@ts-ignore`, no `@ts-expect-error`, and no `!` non-null assertion.
- Override tags, line breaks, and timing stay. Only the words change.
- One provider per session: `claude`, `gpt`, `gemini`, or `mistral`. That provider supplies both models.
- Presets are `save`, `balanced`, and `best`. Save is the smallest escalation set. Best is the largest.
- The app writes `{note: short reason}` at the end of the dialogue text, outside the tags. Reasons are in the target variant. A failed line keeps the English and gets `{note: tradução falhou}`.
- Notes stay in the exported ASS. Flags live in the session. Assisted export is blocked while any flag is open.
- The characters-per-second limit defaults to 17.
- Batches hold 25 dialogue lines. The last batch may be shorter.
- The English file is never overwritten. The proposed output is `<source-stem>.pt-pt.ass` or `<source-stem>.pt-br.ass` beside the source.
- The test suite never calls a live provider and never opens an Electron window.
- The installer ships one LGPL `ffmpeg` for the host platform, unpacked outside `asar`. Honya calls that path and does not search `PATH`.
- Commit messages are one line, `type: subject`, lowercase imperative, no period, no body, and no co-author trailer.

`package.json` depends on `ass-compiler` and has devDependencies `typescript`, `vitest`, `eslint`, and `typescript-eslint`. `readAss` calls `parse` from `ass-compiler` and maps `events.dialogue` in file order:

```ts
import { parse } from "ass-compiler"
import type { DialogueCue } from "./script"

export function readAss(text: string): DialogueCue[] {
  const parsed = parse(text)
  return parsed.events.dialogue.map((dia, index) => ({
    index,
    style: dia.Style,
    name: dia.Name,
    startMs: Math.round(dia.Start * 1000),
    endMs: Math.round(dia.End * 1000),
    raw: dia.Text.raw,
    visible: dia.Text.combined,
  }))
}
```

- [ ] **Step 3: Write minimal implementation**

Count `{` and `}`. Unequal counts return `{ ok: false }`. Otherwise split the raw string with `/(\{[^}]*\})/g`, copy every brace block through unchanged, and place `words` in the first text piece. Later text pieces become empty. If `words` does not contain the same number of `\N` sequences as the original text pieces joined, throw `Error("line breaks changed")`. This does not reinterpret tag bodies. ass-compiler already parsed them.

- [ ] **Step 3: Write minimal implementation**

`styles.css` sets the page background to `#f3efe6`, the card to `#faf7f2`, the ink to `#2a2420`, and the orange to `#e36b1e`. The card has a 1.5px ink border and `box-shadow: 7px 7px 0 #2a2420`. The review body is a two-column grid. The right column is separated by a dashed ink border. Notes and the Accept button use orange. `render` returns a string for the active screen. Review shows the header `series · fileName · openFlagCount flags` and `variant · preset`, the faded previous and next lines, the current words, the note, the English, and Accept. When `proposal` is set, the right column lists sibling lines and the rule text with actions `Save to series`, `Save to base`, and `Decline rule`. Start shows file, variant, series, provider, preset, video, and frame setting, and includes a control that creates a series profile. Styles lists every style with its guess. Ambiguous names have two actions, `Dialogue` and `Skip`. Accepting the list sets `styleListAccepted`. Importing an example script reads it with `readAss`, copies the visible words from styles the user marked as dialogue, and calls `importExample`. Preflight shows line count, frame count, provider, preset, and output path. Run shows the batch index and the latest line. Profiles shows the base rules, example script names, the series list, and fields for the provider key plus the cheap and strong model ids. `index.html` links `styles.css` and a script that calls `render`.
